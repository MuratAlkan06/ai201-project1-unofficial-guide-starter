# Decision Log

## ADR-001: Embedding model, vector store, and top-k
**Status:** Accepted (2026-06-10)
**Context:** Course RAG over 15 r/SJSU threads (< 1 MB, a few hundred chunks), CPU laptop, Python 3.13, free/local tooling, graded on clarity and reproducibility.
**Options considered:** Embedding — all-MiniLM-L6-v2 vs all-mpnet-base-v2 vs bge-small-en-v1.5. Store — numpy/sklearn cosine vs FAISS vs ChromaDB. Top-k — 3 vs 5 vs 8-10.
**Decision:** all-MiniLM-L6-v2 embeddings; ChromaDB persistent local collection; top_k=5 exposed as a tunable parameter. No new dependencies (sentence-transformers==3.4.1, chromadb>=0.6.0 already pinned).
**Addendum (risk critique, same date):** the collection MUST be created with hnsw:space="cosine" (Chroma defaults to L2; the space cannot be changed after creation), and a minimum-similarity refusal floor gates retrieval — below it the system answers "the corpus doesn't cover this" instead of summarizing irrelevant chunks. Floor value is calibrated empirically at M4 (not a design-time constant).
**Consequences:** fastest/smallest local setup; embeddings cached for reproducible grading; free source-attribution metadata via Chroma; multi-perspective k suited to threaded discussion. ChromaDB is the complexity ceiling — no FAISS/ANN at this scale.
**Revisit triggers:** corpus > ~10k chunks (ANN); model-attributable retrieval misses on slang/nicknames (trial bge-small-en-v1.5); chunks approaching 256 word-pieces (longer-context model or lower k); non-English content (multilingual model).
**Resolved at M4 (2026-06-10):** refusal floor calibrated to **0.52** (`retrieval.py: REFUSAL_FLOOR`). Measured: the canonical out-of-corpus probe "Professor Smith CS 999" peaks at 0.479 and clearly off-domain probes lower still (taxes 0.353, hiking 0.269), while the weakest in-corpus eval question (Q5) peaks at 0.558 — 0.52 splits the gap with ~0.04 margin on each side. Known limitation: an unknown professor asked in the eval questions' exact register ("What do students say about Professor Smith's CS 999 class?") scores 0.596, above any floor that still admits Q5; no similarity floor can reject it, so the M5 grounded prompt ("answer only from retrieved chunks") is the documented backstop.
**Revisit trigger exercised at M4:** trialed `bge-small-en-v1.5` per the slang-miss trigger after the merged Gao chunk ranked 233/283 on eval Q5. The trial improved passage ranking (Q4's "weren't positive" chunk: rank 9 → 1; Gao chunk: 233 → 109) but compressed the similarity scale until floor separation vanished (min eval best 0.707 vs max probe best 0.702). **Rejected** — the refusal floor is architecturally required and MiniLM's wider score spread supports it; the Q5 miss was addressed by ADR-003 instead.

## ADR-002: Comment-aware chunking with vertical context anchoring
**Status:** Accepted (2026-06-10, ratified at M1 freeze)
**Context:** Corpus is comment-structured r/SJSU threads with a bimodal comment-length distribution (40-120-word substantive opinions vs sub-25-word one-liners) and occasional oversized structured post bodies (kighem.txt ~1,300 words). High-value answers are short and lose their professor/course anchor when separated from thread title or parent comment.
**Options considered:** (1) fixed-size sliding window (~200 wp / 40 overlap) — slices mid-opinion, rejected; (2) pure per-comment chunking — emits noise one-liners, leaves oversized bodies unsplit; (3) hybrid.
**Decision:** Hybrid: one chunk per comment; replies under ~15 word-pieces merge into their parent chunk; oversized post bodies split on existing markdown headers with section-label echo; every chunk prefixed with thread title (+ parent snippet for replies); ~200 word-piece ceiling (MiniLM truncates at 256); header fields routed to Chroma metadata, never embedded.
**Consequences:** self-contained attributable chunks; high-value one-liners survive with course/professor context; uneven chunk sizes by design; comment score metadata captured but unused (deferred re-rank signal).
**Open at M3:** title-prefix compaction for very long titles (truncate vs compact — measure budget pressure first).
**Resolved at M3 (2026-06-10):** title prefix is trimmed to 40 word-pieces with a trailing ellipsis (`ingest.py: TITLE_PREFIX_MAX_WP`); measured across the corpus, only `kighem.txt`'s 43-wp title exceeds the cap — all 14 other titles embed in full. Word-pieces are counted with the actual `all-MiniLM-L6-v2` tokenizer, not an approximation. Corpus-wide result: 283 chunks, max 192 wp, 0 violations of the 200-wp ceiling.

## ADR-003: MMR diversity re-rank at retrieval
**Status:** Accepted (2026-06-10, M4)
**Context:** Plain cosine top-5 measurably returns single-thread monocultures: the top-10 for eval Q1/Q2/Q4 is one thread each, and Q5's top-4 were sibling replies from a single `c81p6a` subtree (mutually inflated by a shared parent-snippet prefix), pushing the kighem/2ljx6r supporting chunks to ranks 6–7 at a 0.009 similarity deficit. This defeats ADR-001's own k=5 rationale — "a representative spread of perspectives (often across multiple threads)".
**Options considered:** (1) plain top-k — fails Q5's supporting-file requirement; (2) hard per-thread cap (max 2/thread) — fixes Q5 but evicts Q4's answer passages (94eap5 thread-internal ranks 3–4); (3) greedy MMR re-rank over an over-fetched pool.
**Decision:** Over-fetch 50 candidates, select 5 by maximal marginal relevance with λ=0.7 (`retrieval.py: FETCH_K, MMR_LAMBDA`). The first selection is always the globally most-similar chunk, so the refusal-floor gate is byte-identical to plain top-k. λ=0.5 was measured and rejected (drags in unrelated ~0.3-similarity chunks).
**Consequences:** Q5 surfaces kighem + 2ljx6r in top-5 spanning 4 distinct threads; Q4 keeps its "work won't be difficult" answer passage; Q1–Q3, Q6 unchanged at file level. Two documented deviations from the AI Tool Plan's M4 examples: (i) the merged Gao chunk is not enumerable by the broad Q5 phrasing (rank 233/283, sim 0.187 — its embedding is dominated by the parent comment's CmpE 187 content) and is instead verified by a targeted query ("Should I take CmpE 187 with Professor Gao?") where it ranks #1; (ii) Q4's "most people… weren't positive" OP chunk ranks 9th by relevance — that passage is the question's premise rather than its answer, and the answer chunk is retrieved.
**Revisit triggers:** eval misses attributable to over-diversification (raise λ toward 1.0); corpus growth changing the redundancy profile; M5 evidence that two same-thread chunks give the generator too little context.

## ADR-004: Grounded generation via Groq + sentinel backstop; Gradio UI
**Status:** Accepted (2026-06-10, M5)
**Context:** Stage 5 must answer only from retrieved chunks, surface student disagreement, cite sources, and refuse out-of-corpus queries. ADR-001's M4 resolution left one documented leak class (an unknown professor asked in the eval questions' register scores 0.596, above any feasible floor) with the grounded prompt as the designated backstop. `.env`'s `GROQ_API_KEY` was a placeholder during M5 implementation, so live behavior is verified by a re-runnable report rather than in-session.
**Options considered:** Model — `llama-3.3-70b-versatile` vs `llama-3.1-8b-instant` (both current Groq production models). UI — Gradio vs Streamlit (both pre-approved in requirements.txt). Citation scheme — model writes URLs vs model cites excerpt numbers.
**Decision:**
- **Model `llama-3.3-70b-versatile`**, temperature 0.2, one-line constants (`generation.py: GROQ_MODEL, TEMPERATURE`). The backstop turns on instruction-following — the model must emit an exact sentinel rather than helpfully improvise about a professor it has excerpts "near" — which favors the 70B over the 8B; latency is irrelevant at single-query scale.
- **Refusal-floor gate runs before any API call** (free, deterministic refusal for the probe classes), and a **`NOT_IN_CORPUS` sentinel** handles the leak class: rule 2 of the system prompt orders the model to reply with exactly that token when the excerpts don't discuss the asked professor/course; `generate_answer()` maps any sentinel-bearing reply to the planning.md refusal string.
- **Citations are excerpt numbers, mapped to URLs outside the model:** chunks are numbered `[n]` in the prompt, the model cites `[n]`, and `collect_sources()` maps numbers to the retrieved threads' URLs deterministically. URLs never enter the prompt, so a cited URL can never be invented or mistyped (test-asserted).
- **Gradio Blocks** (`app.py`) over Streamlit: the app is a plain importable module whose `ask()` is unit-smoke-testable in-process, whereas `streamlit run` re-executes a script in its own process and resists import-based testing. Single new dependency either way; `gradio>=6.9.0` uncommented in requirements.txt (installed 6.17.3).
**Consequences:** out-of-corpus probes cost zero API calls; cited URLs are always real retrieved threads; the leak-class refusal depends on model compliance with rule 2 and is red-teamed by `generation.py`'s live report (`LEAK_PROBE`) once a real key is present; API/auth failures surface as an actionable message in the UI instead of a stack trace.
**Revisit triggers:** Groq deprecates `llama-3.3-70b-versatile` (swap the constant per their migration notice); live red-team shows sentinel non-compliance (tighten rule 2, add few-shot refusal examples, or JSON-mode structured output); UI needs beyond single-query (chat history → Gradio chat components).
